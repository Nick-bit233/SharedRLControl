# 五阶段课程学习训练结果分析报告

## 0. 摘要

本报告分析了五阶段课程学习（30→60→100→150→200 障碍物）的完整训练结果。

**核心结论：Stage 1 学习成功，但从 Stage 2 开始出现持续退化，Stage 4 发生灾难性崩溃，Stage 5 部分恢复但不稳定。当前模型无法可靠地完成高密度隧道避障任务。**

| 阶段 | 障碍物 | 最终成功率 | 最终碰撞率 | 最终回报 | 状态 |
|------|--------|-----------|-----------|---------|------|
| Stage 1 | 30  | 96.1% | 3.9%  | +273.30  | ✅ 成功 |
| Stage 2 | 60  | 72.3% | 19.9% | -702.27  | ⚠️ 退化 |
| Stage 3 | 100 | 44.9% | 28.5% | -1369.93 | ❌ 持续恶化 |
| Stage 4 | 150 | 1.95% | 98.1% | -121.43  | ❌ 灾难性崩溃 |
| Stage 5 | 200 | 32.4% | 67.6% | -69.17   | ⚠️ 部分恢复，不稳定 |

## 1. 各阶段详细分析

### 1.1 Stage 1（30 障碍物）— ✅ 成功

| 步数 | 回报 | 成功率 | 碰撞率 | Episode长度 | 高度惩罚 |
|------|------|--------|--------|------------|---------|
| 32K | -6.54 | 25.4% | 74.6% | 364.8 | 0.000 |
| 32.8M | +231.97 | 100% | 0.0% | 607.3 | 0.105 |
| 65.6M | +40.96 | 97.3% | 2.7% | 600.6 | 0.146 |
| 98.3M | +148.78 | 95.3% | 4.7% | 595.9 | 0.059 |
| 131.1M | +262.51 | 95.7% | 3.9% | 597.5 | 0.023 |
| 163.9M | +273.30 | 96.1% | 3.9% | 600.7 | 0.019 |

**分析**：Stage 1 是完全成功的。策略从零开始快速收敛，在32.8M步时即达到100%成功率（过度拟合的短暂现象），随后稳定在96%。高度惩罚逐渐降低，说明策略学到了在正确高度飞行。回报从 -6.54 稳步上升到 +273.30。

**关键观察**：
- 30个障碍物的难度适中，策略能充分学习
- Episode 长度稳定在 ~600 步，接近最大值，说明几乎所有 episode 都能存活到终点
- Task reward 稳定在 0.69-0.79，说明速度跟踪也学得不错

### 1.2 Stage 2（60 障碍物）— ⚠️ 末期退化

| 步数 | 回报 | 成功率 | 碰撞率 | Episode长度 | 高度惩罚 |
|------|------|--------|--------|------------|---------|
| 32K | +171.54 | 97.3% | 2.3% | 602.0 | 0.056 |
| 32.8M | +249.99 | 95.3% | 4.7% | 598.2 | 0.025 |
| 65.6M | **-341.89** | **87.9%** | **10.9%** | 591.0 | **0.456** |
| 98.3M | +155.81 | 97.7% | 2.0% | 603.8 | 0.035 |
| 131.1M | +184.40 | 98.0% | 2.0% | 603.1 | 0.067 |
| 163.9M | **-702.27** | **72.3%** | **19.9%** | **559.8** | **0.679** |

**分析**：Stage 2 展现了严重的训练不稳定性。

1. **良好的开始**：从 Stage 1 的 checkpoint 继承后，初始就有 97.3% 的成功率，说明策略对60个障碍物有一定泛化能力
2. **中期波动**：在 65.6M 步处出现第一次显著下降（回报 -341.89，高度惩罚飙升至 0.456），随后恢复
3. **末期崩溃**：最终评估出现灾难性退化——成功率降至 72.3%，碰撞率升至 19.9%，高度惩罚高达 0.679

**关键问题**：
- **高度惩罚激增是核心信号**：0.056→0.679，表明策略在学习"飞高来避开障碍物"，但同时被高度惩罚严重打击
- **最终 checkpoint 是最差的表现**：这意味着传递给 Stage 3 的是一个已经退化的模型
- 回报波动极大（+250 到 -702），训练不稳定

### 1.3 Stage 3（100 障碍物）— ❌ 持续恶化

| 步数 | 回报 | 成功率 | 碰撞率 | 飞出边界 | 高度惩罚 |
|------|------|--------|--------|---------|---------|
| 32K | -775.21 | 67.97% | 25.78% | 6.64% | 0.663 |
| 32.8M | -735.31 | 60.55% | 30.86% | 8.59% | 0.664 |
| 65.6M | -802.19 | 60.16% | 35.55% | 4.30% | 0.655 |
| 98.3M | -1001.77 | 50.00% | 37.50% | 12.50% | 0.826 |
| 131.1M | -1118.49 | 49.61% | 34.77% | 15.63% | 0.932 |
| 163.9M | -1369.93 | 44.92% | 28.52% | **26.56%** | **1.160** |

**分析**：Stage 3 从退化的 Stage 2 checkpoint 出发，在更难的100障碍物环境中持续恶化。

**关键发现**：
1. **"飞出边界" (above_bound) 比例急剧上升**：0% → 6.64% → 26.56%，这是策略为了避开障碍物而选择飞出隧道上边界的明确证据
2. **高度惩罚持续膨胀**：0.663 → 1.160，进一步确认策略在高度方向上的异常行为
3. **碰撞率先升后降，但飞出边界率在上升**：碰撞从35.55%降至28.52%，但飞出边界从4.3%升至26.56%——策略学会了一种"逃避策略"：与其撞墙，不如飞出隧道
4. **任务奖励稳定但无意义**：task_reward 维持在 0.71-0.78，说明速度跟踪没问题，但避障完全失败

### 1.4 Stage 4（150 障碍物）— ❌ 灾难性崩溃

| 步数 | 回报 | 成功率 | 碰撞率 | 飞出边界 | Episode长度 | 高度惩罚 |
|------|------|--------|--------|---------|------------|---------|
| 32K | -1194.14 | 48.44% | 30.08% | 21.48% | 499.8 | 1.096 |
| 32.8M | -1460.42 | 41.80% | 30.47% | 28.13% | 487.3 | 1.330 |
| 65.6M | -1145.28 | 41.41% | 39.06% | 19.53% | 479.5 | 1.106 |
| 98.3M | **-134.88** | **16.41%** | **82.81%** | **0.78%** | **334.2** | **0.081** |
| 131.1M | -59.33 | 26.17% | 73.44% | 0.39% | 351.5 | 0.012 |
| 163.9M | **-121.43** | **1.95%** | **98.05%** | **0.00%** | **217.7** | **0.000** |

**分析**：Stage 4 出现了两种截然不同的行为模式切换。

**Phase A（步 0-65.6M）——延续 Stage 3 的"逃避策略"**：
- 高度惩罚 > 1.0，飞出边界 20-28%
- 碰撞率 30-39%，成功率 41-48%
- 策略仍在尝试通过飞高来避障

**Phase B（步 98.3M-163.9M）——崩溃为"快速撞墙"策略**：
- 高度惩罚骤降至 0（策略不再飞高）
- 飞出边界降至 0%（策略不再飞出隧道）
- 碰撞率飙升至 82-98%
- Episode 长度从 500 缩短至 218 步
- **策略学到的是"直飞撞墙快速结束 episode"**

**这是典型的策略崩溃（policy collapse）**：当高度惩罚过重时，策略放弃了飞高避障的策略；但在没有其他有效避障能力的情况下，策略退化为最简单的行为——直飞前方。

**Task reward 反而上升（0.69→0.92）的悖论**：因为策略全速直飞，速度匹配反而变好了。这暴露了奖励函数的设计缺陷——任务奖励和安全目标部分冲突。

**退化阶段（评估 14→21）**：在达到峰值后，性能持续下降。成功率从 75.78% 降至 32.42%，碰撞率从 23.83% 升至 67.58%。

**退化原因分析**：
1. **reg_coeff 增长过度**：当成功率达到 90% promotion 阈值后（可能在EMA smoothing下触发），reg_coeff 开始增大，迫使策略减小残差（即减少对用户输入的修正），导致避障能力下降
2. **PPO 训练不稳定**：长时间训练中 on-policy 方法容易出现性能振荡
3. **200 障碍物的固有难度**：即使策略一度达到 75.78%，200 障碍物的密度可能已接近物理极限（LiDAR 4m 范围下）

## 2. 跨阶段问题诊断

### 🔴 问题 #1：错误的 Checkpoint 传递策略

**当前行为**：每个阶段结束时保存 `checkpoint_final.pt` 并传递给下一阶段。

**问题**：训练结束时的 checkpoint 不一定是最佳的。Stage 2 的最佳性能出现在 131.1M 步（98.0% 成功率），但传递给 Stage 3 的是 163.9M 步的 checkpoint（72.3% 成功率）。这直接导致了后续所有阶段从一个退化的起点出发。

**影响评估**：**致命**。Stage 2 如果传递最佳 checkpoint，Stage 3 的起点可能是 98% 而不是 68%。

### 🔴 问题 #2：高度逃逸策略（Height Exploitation）

跨阶段数据清晰显示策略学到了一个不良行为模式：

```
Stage 1: 高度惩罚 0.019, 飞出边界 0%     → 正常飞行
Stage 2: 高度惩罚 0.679, 飞出边界 7.8%    → 开始飞高
Stage 3: 高度惩罚 1.160, 飞出边界 26.6%   → 大量飞出隧道
Stage 4: 高度惩罚 0.000, 飞出边界 0%      → 放弃飞高，直接撞墙
```

策略发现"飞到隧道顶部"可以避开很多障碍物（因为障碍物高度 4-10m，而隧道可能更高），但高度惩罚的梯度阻碍了这个策略，最终策略在两个不良选择间振荡。

### 🟡 问题 #3：每阶段训练步数不足

Stage 1-4 各自只有 5010 次迭代（≈163.8M 环境帧），在更复杂的环境中可能不够：
- Stage 1 在 5010 步内收敛（30 障碍物足够简单）
- Stage 2 在约 4000 步时性能还很好（131.1M），但最后 1000 步发生退化
- Stage 3 和 Stage 4 从未收敛

### 🟡 问题 #4：难度跳跃过大

障碍物数量的跳跃：30 → 60 → 100 → 150 → 200

每一步都是 **上一阶段的 1.5-2 倍**。结合障碍物宽度和高度也在增大，实际难度增长可能是超线性的。

### 🟡 问题 #5：Stage 5 的 reg_coeff 课程设计问题

reg_coeff 课程的意图是：当成功率高时增大正则化（让策略更贴近用户输入）。但这有一个根本矛盾：

- 在高障碍物密度下，策略**必须**大幅修正用户输入才能避障
- 增大 reg_coeff 等于限制策略的修正能力
- 这导致成功率先升（通过学习）后降（被正则化拉回）

- 在200个障碍物场景下 75% 成功率仍意味着 ~24% 碰撞率
- 这个 checkpoint 可能位于 `checkpoint_13000.pt` 或 `checkpoint_14000.pt` 附近
- 需要验证其在不同随机种子下的稳健性

### 3.4 整体项目评估

课程学习框架（`run_curriculum.py`）的工程实现是完善的。主要问题在训练策略和超参数层面，不在代码实现层面。

## 4. 优化建议（按优先级排序）

### P0：使用 Best Checkpoint 而非 Final Checkpoint

**改动最小，效果最大的改进。**

```python
# run_curriculum.py 修改建议：
# 不再使用 checkpoint_final.pt，而是使用评估成功率最高的 checkpoint

# 在 train.py 中，tracking best checkpoint:
best_success = -1.0
best_ckpt_path = None

# 在 evaluate() 后：
if current_success > best_success:
    best_success = current_success
    best_ckpt_path = save_best_checkpoint(policy)
```

**具体实施**：
1. 在 `train.py` 的评估循环中记录最佳成功率
2. 额外保存 `checkpoint_best.pt`
3. 在 `final_checkpoint_path.txt` 中写入 best checkpoint 的路径（而非 final）
4. 或者在 `run_curriculum.py` 中实现选择逻辑

### P0：增加早停 + 回退机制

当检测到训练退化时（例如：成功率连续3次评估下降超过10%），提前终止当前阶段。

```python
# 伪代码
if success_rate < best_success * 0.85:  # 成功率下降超过15%
    degradation_count += 1
    if degradation_count >= 3:
        print("Early stopping: performance degradation detected")
        # 回退到 best checkpoint
        policy.load_state_dict(best_state_dict)
        break
```

### P1：调整课程难度梯度

**更平缓的进阶**：

```
当前：30 → 60 → 100 → 150 → 200  (×2, ×1.67, ×1.5, ×1.33)
建议：30 → 50 → 80 → 110 → 150  (每步 ×1.3~1.5)
```

同时**固定障碍物尺寸范围**在前几个阶段：
```yaml
# Stage 1-3: 固定尺寸
obstacle_width_range: [0.4, 0.8]
obstacle_height_range: [4.0, 8.0]

# Stage 4-5: 逐步增大
obstacle_width_range: [0.4, 1.0]
obstacle_height_range: [4.0, 10.0]

# Stage 6-7: 最大难度
obstacle_width_range: [0.4, 1.1]
obstacle_height_range: [4.0, 10.0]
```

### P1：修复高度逃逸问题

两个互补方案：

**方案 A：增大高度惩罚权重 + 硬约束**
```python
# 当前：-8.0 × penalty_height
# 建议：-20.0 × penalty_height + 强制终止

# 如果飞出高度边界，直接终止 episode 并给予碰撞级别的惩罚
if above_bound:
    terminated = True
    reward += crash_penalty  # -10.0
```

**方案 B：缩小隧道高度范围使其与障碍物高度一致**
让障碍物真正填满隧道截面，使"飞高"不再可行。

### P1：Stage 5 去除或修正 reg_coeff 课程

当前的 reg_coeff 课程在高障碍物密度下是有害的：

```python
# 选项 1：完全禁用 reg_coeff 课程
curriculum.enable = False

# 选项 2：大幅提高 promotion_threshold
curriculum.promotion_threshold = 0.98  # 只在接近完美时才增大正则化

# 选项 3：降低 max_reg_coeff
curriculum.max_reg_coeff = 0.05  # 从 0.3 降低
```

### P2：增加每阶段训练步数（对中间阶段）

```yaml
# 当前
stage1-4: max_iterations = 5010
```

```python
# Stage 1: lr = 1e-4 (from scratch, need fast learning)
# Stage 2: lr = 7e-5 (fine-tuning, need stability)

```

微调已有策略时使用更小的学习率可以减少灾难性遗忘。

### P3：改进诊断和监控

在 `train.py` 中增加以下监控指标：
- `reg_coeff` 当前值（对 Stage 5 尤其重要）
- `residual_norm`：残差的平均范数
