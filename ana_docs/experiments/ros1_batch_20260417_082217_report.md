# ROS1 对比实验结果报告：`batch_20260417_082217`

## 1. 实验概况

- **数据目录**：`SharedRLControl/ros1/results/batch_20260417_082217`
- **对比方法**：`RL` vs `IPC`
- **实验规模**：100 个地图 batch，每个 batch 10 个用户随机种子，计划共 2000 次试验
- **地图配置**：每张地图 15 个障碍物，`cuboid_ratio=0.5`
- **目标位置**：`goal_x = 10.0`
- **碰撞阈值配置**：`collision_dist = 0.05`
- **渲染与设备**：CPU、无 GUI、无 RViz

## 2. 数据完整性说明

本批实验共生成 **2000 份 `run_summary.json`**，其中：

- `RL`：1000 / 1000 完整
- `IPC`：1000 / 1000 完整，但其中 **12 次为零样本超时**（`samples=0`、`data_file=""`）

因此，报告采用两种口径：

1. **全量试验口径**：基于全部 2000 份 `run_summary.json`，用于统计成功率、碰撞率、超时率。
2. **有效轨迹口径**：基于 `analysis/metrics.csv`，用于统计轨迹长度、平均速度、最小障碍距离等连续指标。该口径下 `RL=1000`，`IPC=988`。

## 5. 结果解读

### 5.1 RL 的主要优势

1. **成功率更高**：54.0% vs 41.4%，配对场景中“仅 RL 成功”比“仅 IPC 成功”多 126 次。
2. **效率更高**：无论看全体有效轨迹还是双成功子集，RL 都显著更快。
3. **路径更短**：RL 成功时平均轨迹长度为 23.54 m，低于 IPC 的 26.08 m。

### 5.2 RL 的主要代价

1. **碰撞风险明显**：13.6% 的碰撞率是当前最主要短板。
2. **方法稳定性有地图依赖**：在少数 batch 上，RL 成功率明显落后 IPC，并伴随 20%~40% 的碰撞率。

### 5.3 IPC 的特点

1. **零碰撞**：在全量 1000 次试验中未记录到碰撞。
2. **保守但慢**：成功率偏低，超时率高达 58.6%，且成功时平均用时接近 RL 的 3 倍。
3. **存在执行层超时问题**：有 12 次 IPC 试验未生成有效轨迹，属于额外的数据质量风险。

## 6. 结论

这批 ROS1 对比实验的主结论是：

- **如果目标是提升通过率与任务效率，RL 明显优于 IPC。**
- **如果目标是严格压低碰撞风险，IPC 仍然更保守。**
- **当前 RL 最值得继续优化的方向不是“更快”，而是“在保持成功率优势的前提下压低碰撞率”。**

从工程落地角度看，当前结果更像是：

- `RL`：**高通过率 / 高效率 / 中等风险**
- `IPC`：**低风险 / 低效率 / 高超时**
