## 1. 关键发现

### 1.1 致命Bug：评估指标全部失效

| 指标 | 期望行为 | 实际值 | 原因 |
|------|---------|--------|------|
| `survival_rate` | 随训练变化 | **恒定 0.5** | key命名错误 |
| `tracking_rmse` | 反映跟踪质量 | **恒定 0.0** | 同上 |
| `intervention_mean` | 反映干预幅度 | **恒定 0.0** | 同上 |
| `collision_rate` | 反映碰撞率 | **恒定 0.5** | 同上 |

**根本原因**: `train.py` 中计算派生指标时使用了错误的key前缀 `eval/stats_*`，而实际eval字典中的key为 `eval/*`（无 `stats_` 前缀）。

```python
# BUG: 这些key不存在，全部返回默认值
collision_rate = info.get("eval/stats_collision", 0.5)      # → 0.5
episode_len = info.get("eval/stats_episode_len", 1.0)       # → 1.0
tracking_sum = info.get("eval/stats_tracking_error_sum", 0.0) # → 0.0
```

**连锁影响**:
- ❌ Best checkpoint 从不更新（survival_rate 恒为 0.5，首次评估即为 "best"）
- ❌ Early stopping 从不触发（survival_rate 从不下降）
- ❌ WandB 曲线无意义（所有派生指标为常数）

### 1.2 奖励失衡：高度惩罚压倒一切

对最后5次评估的加权奖励分析：

| 奖励项 | 原始值 | 系数 | 加权贡献 | 占比 |
|--------|--------|------|---------|------|
| `r_tracking` | -0.746 | ×1.0 | **-0.746** | 9.3% |
| `r_safety` | -0.157 | ×3.0 | **-0.470** | 5.8% |
| `p_smooth` | +0.067 | ×(-0.3) | **-0.020** | 0.2% |
| `p_height` | +0.681 | ×(-10.0) | **-6.811** | **84.7%** |

**高度惩罚贡献了85%的负回报**。策略的首要学习目标变成了"保持正确高度"，而非"跟踪人类输入"或"避障"。

### 1.3 无人机几乎不移动

| 指标 | 值 | 说明 |
|------|-----|------|
| `debug_pos_world` | 1.3 ~ 2.8m | 在40×40m地图中仅占7% |
| `tracking_error` | 0.6 ~ 1.0 | 高——策略偏离人类指令 |
| `intervention_norm` | 0.3 ~ 0.45 | 高——策略大幅修改输入 |

**原因**: 多模态随机输入（perlin+直线+弧形+悬停）的净位移趋近于零。策略学会了原地悬停+控制高度，而非跟随人类指令飞行。

### 1.4 碰撞率无改善

碰撞率在整个训练过程中在 5%~27% 之间振荡，无收敛趋势。同时 above_bound+below_bound 终止占 2%~18%。

## 3. 问题根因分析

### 3.1 奖励结构问题
- 高度惩罚系数(-10.0)是跟踪奖励(1.0)的**10倍**
- 高度无惩罚区间仅 [2.3m, 7.7m]（bounds ± 0.2m margin）
- 障碍物高度 [6, 12]m → 上方被障碍物封堵，下方被高度惩罚限制

### 3.2 观测空间缺陷
- **无高度信息**: 策略无法感知自身绝对高度，只能通过惩罚信号间接学习
- **无位置信息**: 策略无法感知自身是否接近地图边界

### 3.3 人类输入设计
- 4种模态均产生z轴速度指令，推动无人机离开安全高度区间
- 与高度惩罚形成根本冲突：跟踪z指令→高度惩罚；忽略z指令→跟踪惩罚

## 4. 修复方案

### 4.1 Bug修复
1. **修复eval key命名**: `eval/stats_*` → `eval/*`

### 4.2 奖励重设计（系数可配置化）
| 奖励项 | 旧系数 | 新系数 | 理由 |
|--------|--------|--------|------|
| `r_tracking` | 1.0 | **3.0** | 跟踪应为主信号 |
| `r_safety` | 3.0 | **5.0** | 安全为第二优先级 |
| `p_smooth` | -0.3 | **-0.1** | 降低以保留探索能力 |
| `p_height` | -10.0 | **-1.0** | 大幅降低，作为软引导 |

### 4.3 高度设计修复
- 扩大无惩罚区间: margin 0.2m → **1.0m**
- 新的无惩罚区间: [1.5m, 8.5m]（原 [2.3m, 7.7m]）

### 4.4 观测增强
- 添加归一化高度信息到观测空间: `z_normalized = (z - h_mid) / (h_range/2)`
- 让策略能够"看到"自己的绝对高度
