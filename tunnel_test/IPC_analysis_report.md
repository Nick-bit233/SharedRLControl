# IPC 算法迁移分析报告

## 一、CIRI 警告信息分析

在运行对比测试时，频繁出现以下两条警告：

```
WARNING: Generated polytope is empty — aborting.
WARNING: Seed points not inside boundary — aborting.
```

### 1.1 "Seed points not inside boundary" 原因分析

**触发条件**：在 `ciri_corridor.py` 第 434-440 行，CIRI 在生成安全走廊前会检查两个种子点 `seed_a`（无人机当前位置）和 `seed_b`（MPC 参考路径点）是否在边界框内。当检测到 `boundary @ [seed, 1] > epsilon` 时触发。

**根本原因**：在 `ipc_controller.py` 的 `_add_sfc_for_step()` 中，边界框定义为以 `mid = (pos_w + goal_w) / 2` 为中心、半径为 `obstacle_query_radius=4.0m` 的正方体。但种子点 `seed_a = pos_w`，`seed_b = goal_w`（A* 路径参考点）。

当无人机当前位置 `pos_w` 和参考点 `goal_w` 之间的距离较大时（例如高速飞行时 lookahead 时间长），其中一个种子点可能刚好落在边界框的边缘或外侧。数值精度（boundary 使用 `<=`，但 epsilon 仅为 `1e-6`）也可能导致边界处误判。

**发生频率**：主要在以下情况频繁出现：
- 无人机高速飞行时（用户速度接近 `max_speed=2.0m/s`）
- MPC horizon 较远步长的参考点偏离无人机位置较多
- 无人机位于隧道转角处，A* 路径弯曲

### 1.2 "Generated polytope is empty" 原因分析

**触发条件**：在 `ciri_corridor.py` 第 561-565 行，CIRI 生成半平面约束后，通过 Chebyshev 中心验证多面体是否有非空内部。如果 LP 求解判定多面体无可行内部，则触发。

**根本原因**：
1. **障碍物密集区域**：当无人机附近障碍物密度高时，CIRI 生成的切平面约束相互矛盾，导致可行域缩小到空集
2. **椭球初始化不良**：seed 线段周围有大量障碍物时，初始椭球被反复收缩到极小，最终切平面相交为空集
3. **边界框太小**：`obstacle_query_radius=4.0m` 在密集隧道中可能导致几乎所有方向都被约束封死

### 1.3 对实验结果的影响评估

| 影响维度 | 影响程度 | 说明 |
|---------|---------|------|
| **安全性** | ⚠️ 中等 | 当 CIRI 失败时，MPC 在该步没有 SFC 约束，退化为无障碍物约束的轨迹优化。此时 MPC 仍有 velocity/acceleration/jerk bounds，但缺少空间约束。`fallback_to_simple=true` 确保不会崩溃，但避障能力降级。 |
| **轨迹质量** | ⚠️ 中等 | 部分 MPC horizon 步长缺少 SFC，导致优化轨迹可能穿过障碍物。实际表现取决于成功生成 SFC 的步数比例。如果前 1-2 步成功、第 3 步失败，短期安全仍有保障。 |
| **碰撞率** | ⚠️ 可能偏高 | 频繁的 SFC 失败意味着避障能力不稳定。在密集障碍物区域，正是最需要 SFC 保护的时候，却最容易失败。这可能导致 IPC 算法的碰撞率高于其在原始环境中的表现。 |
| **公平性** | ⚠️ 影响对比 | 如果 CIRI 失败率很高（>30%），则 IPC 算法实际上大部分时间运行在降级模式下，与原始 C++ 实现的表现不具可比性。对比结果可能低估 IPC 算法的真实能力。 |
| **推理性能** | ✅ 微小 | CIRI 失败时提前返回 None，反而减少了计算量（跳过 Chebyshev、MVIE 等后续步骤），对帧率有轻微正面影响。 |

**结论**：这两条警告**会显著影响实验结果的公平性**。建议在报告中统计 CIRI 成功率作为额外指标，并在后续版本中修复边界框计算逻辑。

### 1.4 建议修复方案

1. **"Seed not inside boundary"**：将边界框扩大以完全包含两个种子点。将 `box_min = mid - radius` 改为 `box_min = np.minimum(pos_w, goal_w) - margin`，确保种子点始终在边界内。
2. **"Polytope empty"**：增加 `obstacle_query_radius`（如 6.0m），给 CIRI 更多空间；或在密集区域自动减少 `max_obstacle_points`，降低约束密度。
3. **增加 epsilon 容差**：将 CIRI 的 epsilon 从 `1e-6` 改为与原版一致的 `1e-10`（更严格的浮点容差），或适度放宽边界检查容差。

## 三、参数差异影响总结

### 3.1 对公平对比影响最大的参数差异

按影响程度排序：

1. **🔴 MPC horizon: 15 → 10**
   - 减少了 33% 的预测窗口（从 1.5s 到 1.0s）
   - 直接影响轨迹优化质量，尤其在需要提前规避的场景
   - **建议**：恢复为 15，接受约 30% 性能损失

2. **🔴 max_sfc_steps: 全部 → 3**
   - 原版为整个 horizon（15 步）生成 SFC，迁移版仅 3 步
   - 后续步缺少空间约束，MPC 可能规划出穿越障碍物的轨迹
   - **建议**：至少提高到 5-8，与 horizon 同步调整

3. **🟡 v_max: ±10.0 → ±3.0**
   - 极大限制了无人机的机动能力
   - 但考虑到隧道场景中 `max_speed=2.0`，3.0 的上限在多数情况下足够
   - **建议**：提高到 ±5.0 以留有余量

4. **🟡 a_max: ±20.0 → ±10.0**
   - 限制了紧急机动能力
   - **建议**：恢复为 ±20.0

5. **🟡 occupancy resolution: 0.1 → 0.2**
   - 降低了障碍物表示精度
   - 加上 inflation_steps=3 实际膨胀半径从 0.3m → 0.6m，过度保守
   - **建议**：保持 0.2（性能考虑），但将 inflation_steps 减少到 2

6. **🟢 A* resolution: 0.1 → 0.5**
   - 路径规划精度降低，但 A* 仅提供粗糙参考路径
   - 后续由 MPC + CIRI 细化，影响有限
   - **建议**：可接受，保持 0.5

7. **🟢 epsilon: 1e-10 → 1e-6**
   - 更宽松的容差可能导致更多边界判定通过，反而减少 "Seed not inside boundary" 错误
   - 但也可能导致数值不稳定的多面体被接受
   - **建议**：恢复为 1e-10 以匹配原版

### 3.2 合理差异（不影响公平性）

- **map_size**: 因场景不同，合理调整
- **FSM frequency**: 受 Isaac Sim 仿真步长限制（60Hz vs 100Hz），不可调
- **lookahead_time / replan_interval**: 作为 FSM 的简化替代，合理
- **缺失的 FSM / 底层控制**: Isaac Sim 提供了等效功能，无需迁移

## 四、建议

### 4.1 短期（保证对比公平性）

1. 在对比报告中明确声明参数差异，尤其是 horizon 和 max_sfc_steps 的减少
2. 统计并报告 CIRI 成功率作为额外指标
3. 修复 "Seed not inside boundary" 的边界框计算逻辑

### 4.2 中期（提升 IPC 表现）

1. 恢复 `horizon=15`，`max_sfc_steps` 提高到至少 5
2. 恢复 `v_max=±10.0`, `a_max=±20.0`
3. 将 `epsilon` 改为 `1e-10`
4. 减少 `inflation_steps` 到 2（补偿 resolution 变化）

### 4.3 长期（完善迁移）

1. 考虑将 CIRI 核心循环用 Cython 或 C 扩展重写，以恢复 horizon=15 + 全 SFC 步而不损失性能
2. 添加 CIRI 成功率监控和自适应参数调整
